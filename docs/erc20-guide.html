¿Qué es ERC20?

Es el estándar de tokens fungibles en Ethereum. "Fungible" = cada token vale lo mismo que otro (a diferencia de un NFT).

USDC, UNI, DAI — todos son ERC20.

Define 6 funciones y 2 eventos que TODO token debe implementar.

Las 6 Funciones

1. totalSupply() → uint256

Cuántos tokens existen

2. balanceOf(address) → uint256

Cuántos tiene una dirección

3. transfer(to, amount) → bool

Mando tokens de MI wallet

4. approve(spender, amount) → bool

Autorizo a otro a gastar mis tokens

5. transferFrom(from, to, amount) → bool

Otro mueve MIS tokens (con permiso)

6. allowance(owner, spender) → uint256

Cuánto me autorizó alguien

Los 2 Eventos

event Transfer(address indexed from, address indexed to, uint256 value);
event Approval(address indexed owner, address indexed spender, uint256 value);

indexed: permite filtrar eventos por ese parámetro (máximo 3 parámetros indexados por evento)

Trazado con Valores Reales

Escenario Inicial

Alice tiene 1000 USDC, quiere mandarle 200 a Bob

Estado inicial:
  balanceOf(Alice) = 1000
  balanceOf(Bob)   = 0
  totalSupply()    = 1000 (Alice los tiene todos)

Caso A: Transferencia directa (Alice → Bob)

Alice llama: transfer(Bob, 200)

Dentro del contrato:
  balanceOf(Alice) = 1000 - 200 = 800  ✓
  balanceOf(Bob)   = 0 + 200   = 200  ✓
  totalSupply()    = 1000 (no cambia, solo se mueven)
  
Emite: Transfer(Alice, Bob, 200)
Retorna: true

Caso B: Alice le da permiso a un Router (DEX) para gastar 500

Estado inicial:
  allowance(Alice, Router) = 0

Alice llama: approve(Router, 500)

Dentro del contrato:
  allowance(Alice, Router) = 500  ✓

Emite: Approval(Alice, Router, 500)
Retorna: true

Caso C: El Router mueve 300 de Alice a Charlie (usando el permiso)

Estado inicial:
  balanceOf(Alice)         = 800
  balanceOf(Charlie)       = 100
  allowance(Alice, Router) = 500

Router llama: transferFrom(Alice, Charlie, 300)

Dentro del contrato:
  require(allowance(Alice, Router) >= 300)  ✓ (500 >= 300)
  
  balanceOf(Alice)   = 800 - 300 = 500  ✓
  balanceOf(Charlie) = 100 + 300 = 400  ✓
  allowance(Alice, Router) = 500 - 300 = 200  ✓ (se reduce el permiso)
  
Emite: Transfer(Alice, Charlie, 300)
Retorna: true

¿Por qué approve + transferFrom en 2 pasos?

Problema de seguridad: Si approve + transfer fueran una sola llamada, el Router podría gastar TODOS mis tokens (no hay límite).

Solución en 2 pasos:

  1. Alice aprueba 500 al Router → approve(Router, 500)
  2. Router solo puede gastar hasta 500 → transferFrom(Alice, ..., amount <= 500)
  3. Cada transferFrom reduce el allowance
Esto es lo que vas a usar cuando el Router del DEX mueva tokens del usuario al Pair.

Diagrama de Flujos

USUAL FLOW (Alice → Router → Pair):

[Alice]
  │
  ├─ 1. approve(Router, 500)     ← da permiso
  │
  ▼
[Router]
  │
  ├─ 2. transferFrom(Alice, Pair, 300)   ← mueve tokens
  │      (gasta del allowance)
  │
  ▼
[Pair contract]

Reglas Importantes

  • transfer revert si balanceOf(sender) < amount
  • transferFrom revert si allowance < amount
  • approve puede sobrescribir (cuidado con race conditions, pero no lo vemos ahora)
  • Eventos Transfer y Approval deben emitirse SIEMPRE (incluso con amount = 0)
